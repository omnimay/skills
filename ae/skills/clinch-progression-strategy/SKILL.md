# 商机推进策略

## 目的

回答"这个单从现在到签约还要过几关、这周该推谁"——**事前·整体推进规划**，不是单次复盘、不是即时异议、不是临门逼单。

**读者读完画面**：①这周该做哪 3-5 件事 ②从当前关到成交还有几关 ③何时该止损或转向 ④绝不能踩的 3 个误判。

---

**三道关键止损闸门**：

| 闸门 | 时点 | 触发动作 |
|---|---|---|
| **Week 2 末** | Champion 没浮现 + 见不到老板 | 重估需求与投入，考虑战略放弃 |
| **Week 6 末** | 试点 4 周仍无数据亮点 | 缩范围 / 战略放弃 |
| **Week 10 末** | 价格拉锯 > 30% 或法务卡关键条款 | 进入临门逼单节奏或重估 |

## 二、销售个人的 5 条关键提醒

> 销售 15 分钟拿到就能动手；不是模板，是判断锚。

### 1. 沉默 14 天 = 黄转红临界点

Demo 后客户没主动联系，14 天内必须破冰——**电话优先**，邮件兜底；不要发长邮件、不要群发、不要发 PPT。

> B 端销售里"沉默"绝大多数不是"在内部走流程"，而是"被其他事挤掉优先级"或"内部有人在反对/观望"。

### 2. 业务副总不是 Champion，是「消级友好方」

真正的 Champion **会做 4 类动作**：①主动约下一次会议 ②主动给你内部情报 ③主动帮你约老板 ④主动帮你挡竞争对手。

> 4 类动作全无 = 他不是 Champion。要么培养，要么找别人（运营总监/采购总监/IT 项目经理/老板助理）。

### 3. 300+ 门店的项目，老板必过手

IT 总监和业务副总都没有最终拍板权。Week 1-2 必须见到老板——越早接触，主动权越大。

> **红旗**：业务副总拒绝或拖延引荐（"还没到时候"/"老板很忙"/"我先跟老板说说"）= VP 自己不想推 / 怕你越级 / 已有备选供应商——需启动侧攻（老板助理/IT 总监/其他高管）。

### 4. POC 试点是 300+ 门店必经关键路径

一次性买断几乎不可能；必经 POC（5-10 家代表性门店 + 4-8 周 + MOU + 真实业务数据 + 业务价值复盘报告）。**试点报告是后续集团采购谈判的弹药**——漏掉 POC = 路径错。

> Week 3 试点协议签订时**同步给初步报价区间**（用于 H2 预算报批，不是最终报价）。区间幅度 15-20%。

### 5. 商务条款要 Week 3 同步给报价区间

商务条款 0 进展 + 客户预算要报批 = 客户内部没法干活。**越晚谈价格，主动权越丢**。

> 付款条件（预付 / 进度款 / 尾款 / 质保金比例）是独立关卡，签约前必谈；**预付款到账才是真成交**（签约 ≠ 收钱）。

## 三、销售最容易踩的 3 个误判

### 误判 1：把"业务副总口头认可"等同于"会买"

- **事实**：功能 OK 是不反对，不是推动。从"不反对"到"推动"还差 10 倍努力。
- **检验动作**：Week 2 看 VP 是否主动约下一次会议 / 帮你约老板 / 提供内部情报。三项都无 → 他不是 Champion。

### 误判 2：把"沉默"等同于"在内部走流程"

- **事实**：沉默 = 被其他事挤掉优先级 / 内部有人在反对或观望。
- **检验动作**：14 天内必须主动破冰。如果破冰后客户仍消极 → 大概率内部有人反对或项目没进优先级。

### 误判 3：把"下半年有预算"等同于"会批给你"

- **事实**：预算要报批 / 金额要进采购流程 / 老板要签字 / 对手要 PK。不主动给框架、不主动见老板、不主动算 ROI，预算永远是别人的。
- **检验动作**：Week 3 必须给到初步报价区间。如果客户不要 → 警惕（可能在比价或根本没打算用你）。

## 四、一句话打法

**本周破冰、本月见老板、本季试点、Q4 签约。任何一步落后 2 周，重新评估是否继续投入。**

落到本周（Day 1-7）：
- Day 1-2：电话业务副总，约 30 分钟会议
- Day 3：技术深聊会（IT 总监 + 业务副总 + 你方架构师）
- Day 4-5：识别 B 计划 Champion + 老板接触铺垫
- Day 7：交付价值测算表 + Week 1 末红线判断

> **Week 1 末自检三项**：IT 异议没闭环 / Champion 没浮现 / 老板接触没启动——Week 2 要么翻盘，要么止损。

## 六、关键判断（3 条核心 Over）

> 这 3 条是销售拍板的判断锚，独立于上面的 5 提醒——用于"路径设计阶段"而非"本周执行"。

- **复杂体量 over 简单节奏** — 300+ 门店 / 集团采购 / 国央企招标节奏是 **12 周起步**；中小企业 / 单店直采 60-90 天。**60 天跑通 300 店 = 自己骗自己**。
- **先小后大 over 一次性买断** — 300+ 门店一次买断几乎不可能，**必经 POC/试点**。**漏掉 POC = 路径错**。
- **采购方式 over 客户类型** — 公开招标 → 国央企模板（立项+招投标三步+合同审+进场）；直采 → 民企模板（无招投标）；外企在华子公司 → 民企模板 + 补全球审批关。

## Boundary

本 skill 只答"从现在到签约怎么推"。不含：商机健康诊断、投入产出重估、单次沟通复盘、即时异议应对、临门逼单执行。

## 附录 A：8 维采集卡（团队 SOP 沉淀）

> 销售个人不一定每次都填——团队 SOP 复用价值，用于周会复盘或季度商机盘点。

| 维度 | 关键问什么 |
|---|---|
| 商机阶段 | 当前关 + 停留时长 + 推进趋势 |
| 关键人 | 五角色（发起/评估/决策/采购/使用方）谁有谁缺 + 态度（**single-threaded = 头号卡点**） |
| 已确认信息 | 需求 / 预算（书面 vs 口头）/ 时间线 / 采购方式 |
| 卡点 | 卡在哪一关 + 卡了多久 + 试过什么 |
| compelling event | 紧迫事件 + 来源（合同到期/监管/财年/招标截止/上级督办）（**无 = 必然拖延**） |
| 竞争 | 友商在不在 + 是否塑造决策标准（**信息缺失 ≠ 没友商**） |
| 客户类型 | 国央企/民企/外企（**采购方式比客户类型更准**） |
| 历史脉络 | 关键节点 + 承诺兑现 |

> 字段定义 + 中国数据源（企查查/天眼查/中国政府采购网/千里马/Boss 直聘；**禁用** LinkedIn/Apollo/G2/Capterra）见 `references/china-adaptation.md`。

## 附录 B：6 类卡点 × R/Y/G（团队 SOP 沉淀）

归到 6 类之一（可并存），每类标严重度——这是"先解什么"的根据。

| 类型 | 一句话判断 |
|---|---|
| 关键人缺口 | EB 没见 / single-threaded / champion 不愿向上推 |
| 流程卡点 | 招标没排期 / 合同审卡 / 付款条件未谈 / 采购方式未核实 |
| 信息缺口 | 决策标准不清 / 痛点没量化 / 预算未书面 / 竞争不明 |
| 竞争卡点 | 友商已落子 / 决策标准被友商塑造 |
| 资源卡点 | 售前/法务/老板站台缺位 / 本机无案例资质 |
| 时机卡点 | 无 compelling event / 预算周期错位（Q4 推执行单 = 推不动） |

**严重度方向**：Red 阻断必须先解 / Yellow 拖慢要排解 / Green 已解或低风险。归因必须给证据——**禁止"感觉卡在关键人"**。

> 6 类信号清单 + 中国专属反例见 `references/blocker-types.md`。

## 附录 C：G1-G7 关卡序列（团队 SOP 沉淀）

按采购方式 / 客户类型选模板。**300+ 门店连锁餐饮民企 = 民企模板 + POC 试点关插入**。

| 关卡 | Entry | Exit | 当前阻碍 |
|---|---|---|---|
| **G1 技术异议关闭** | Demo 已完成 | IT 总监技术问题书面应答 + 内部评估通过 | 仅口头提问，无书面应答 |
| **G2 EB access** | 业务副总愿向上推 / 多线程找到 EB | 与老板面谈 + 老板认可方向 | 老板完全未接触 |
| **G3 决策标准对齐 + POC 设计** | EB 认可方向 | 5-10 家代表性门店清单 + MOU 签署 + 试点周期（4-8 周） | 当前连 POC 都没提 |
| **G4 POC 执行 + 业务价值复盘** | MOU 签署 | 试点跑完 + 真实业务数据 + 复盘报告 | 当前远未到 |
| **G5 集团采购 / 预算书面化** | 试点报告交付 | 预算书面化（PO / 审批单）+ 集团采购触发 | "下半年有但要报批"未书面 |
| **G6 商务条款 + 合同审** | 预算书面化 | 价格 / 模块清单 / 续约 / 数据归属 / SLA 共识 + 合同会签过 | 商务条款零谈 |
| **G7 付款条件** | 合同会签过 | 付款条件谈妥（预付 / 进度款 / 尾款 / 质保金比例）——**签约前必谈** | 付款条件未谈 |

**通用尾关**：付款条件独立关卡，签约前必谈；**预付款到账才是真成交**（签约 ≠ 收钱）。

## 附录 D：5 阶段动作表（owner-deadline 模板）

> 团队周会 / 月度复盘用。销售个人 Day 1-7 的具体动作从「附录 D 阶段 1」里直接挑。

**关键约束**：每行 5 字段（动作 / owner / deadline / 验收标准 / 内部协调）；owner 区分清楚（销售/售前/法务/财务/老板/champion）；内部协调独立成行；本周聚焦 3-5 行。

### 阶段 1：技术异议关闭 + EB access 铺垫（Week 1-2）

- 售前：IT 总监 3 个技术问题书面应答（数据迁移 / API 限流 / 多门店并发）——本周三交付
- 销售：约 IT 总监 + 业务副总技术答疑会（≤60 min，架构师对架构师）——本周五
- 销售：业务副总引荐老板（明确话术"既然产品功能 OK，想向老板汇报下整体方案"）——T+10
- 销售 → 本机老板：老板对老板站台备战略对齐话术——T+14
- 销售：摸 IT 总监真实动机（通过业务副总侧面探：友商标准/个人保留/真技术卡点）——本周四

### 阶段 2：POC 试点设计 + 竞争重塑（Week 3-4）

- 销售+售前：选 5-10 家代表性门店清单（一线/二线/商圈/社区场景）+ MOU 模板就绪——T+21
- 销售：摸友商（IT 总监/业务副总/企查查/行业群）——T+18
- 售前：围绕 IT 3 问题重塑决策标准（把本机强项变必选项）——T+21
- 销售+售前：Landmine（在技术答疑/老板汇报里埋友商常踩坑）——T+21

### 阶段 3：POC 执行 + 商务条款启动（Week 5-8）

- 销售+售前：POC 启动（5-10 家门店真实业务数据，售前现场支持）——T+56
- 销售：启动商务条款沟通（先方案形式提交，不直接报价）——T+35
- 销售：核实采购方式（直采/框架协议/单一来源）——T+35
- 销售：推动预算书面化（"下半年报批"→ 具体月份 + 报批流程 + 决策人）——T+42

### 阶段 4：试点验收 + 商务谈判（Week 9-10）

- 售前：POC 业务价值复盘报告交付（试点报告作为集团采购谈判弹药）——T+60
- 销售：正式报价给到采购 + 商务谈判（价格/付款/合同条款）——T+70
- 销售→法务：法务过稿 + 用印流程——T+75

### 阶段 5：签约 + 首付款（Week 11-12）

- 销售：合同签署 + 预付款到账（**预付款到账才是真成交**）——T+84
