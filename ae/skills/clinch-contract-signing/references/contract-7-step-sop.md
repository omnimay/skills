# contract-7-step-sop.md

> 7 步签约主线 SOP 详细说明 + 时间节点 + RACI

## 步骤 1：合同起草

**输入**：谈判结果清单（金额 / 起止 / SLA / 付款 / 知识产权 / 违约）+ 模板版本号（v1.x）

**输出**：DOCX 草稿（带模板版本号水印）

**责任方**：

- **R**（执行）：销售 AE/AM + 法务助理
- **A**（问责）：法务总监
- **C**（咨询）：销售经理 SM（如金额 ≥ 100 万）
- **I**（知情）：财务（如付款节奏复杂）

**动作清单**：

1. 拉取谈判结果（从谈判与报价环节的输出物）
2. 选模板（标准 / SLA / 数据合规 / 涉外，详见 `cn-contract-clauses.md`）
3. 填变量字段：甲方主体 / 标的 / 金额 / 起止 / 付款 / SLA / 联系人
4. 法务助理审一次（条款完整性 / 风险点）
5. 标注模板版本号 v1.x + 起草日期 + 起草人

**时间上限**：2 个工作日

**红线**：

- 不接受手写合同（必须模板化）
- 不接受"金额 + 起止 + 联系人"任一字段缺失

---

## 步骤 2：内审（销售 / 法务 / 财务三方过会）

**输入**：DOCX 草稿

**输出**：审批意见 + 修订稿 + 评审记录表

**责任方**：

- **R**：法务助理（组织）+ 销售（条款确认）+ 财务（付款条款）
- **A**：法务总监
- **C**：销售经理 SM（如金额 ≥ 100 万）
- **I**：CSM（如已分配）

**动作清单**：

1. 法务审条款：合法性 / 完整性 / 风险点（参考中银律师 / 君合律师的 6 步审查）
2. 销售确认条款：谈判结果落字是否准确
3. 财务审付款：金额 / 节奏 / 发票 / 逾期违约金是否合理
4. 出具三方签字的评审记录表（电子签 / 邮件确认均可）
5. 修订稿落地（DOCX 带修订痕迹）

**时间上限**：1 个工作日

**红线**：

- 任何条款疑问未解决 → 不进入客户 review
- 财务对付款条款有异议 → 必先解决再外发

---

## 步骤 3：客户法务 review 接收

**输入**：修订稿（DOCX 带修订痕迹 / 邮件正文）

**输出**：客户修改意见（DOCX 修订 + 邮件回复）

**责任方**：

- **R**：客户法务 / 客户采购
- **A**：客户项目对接人（业务侧）
- **C**：客户公司领导（如金额重大）
- **I**：我方销售

**动作清单**：

1. 销售发 DOCX 修订稿给客户（不直接发 PDF——客户需要编辑）
2. 客户下载 / 修订 / 标红 / 加批注
3. 客户回传 DOCX（含客户修订痕迹）
4. 邮件确认接收 + 注明对方接收人 / 时间

**时间节奏**：客户节奏决定（建议设 5 个工作日 soft deadline）

**红线**：

- 不接受客户在 Word 之外修改（截图 / 微信 / 电话口头）
- 不接受客户删改模板版本号 / 模板来源标识

---

## 步骤 4：修订迭代（差异对比 + 红线保护）

**输入**：客户修改意见（DOCX）

**输出**：双方确认稿（git diff 可视化）

**责任方**：

- **R**：销售 + 法务
- **A**：法务总监
- **C**：销售经理 SM（红线条款必过 SM）
- **I**：客户对接人

**动作清单**：

1. 用 diff 工具对比客户修订 vs 我方底线（详见 `contract-redlines.md`）
2. 标出**红线条款**（不可让步）+ **可让步条款**（可换条件）
3. 销售回客户：哪些接受 / 哪些不接 / 哪些可换条件
4. 2-5 轮迭代直到双方确认
5. git 提交每轮版本（v0.1 / v0.2 / v1.0 最终版）

**时间上限**：2-5 轮 × 1 个工作日 / 轮

**红线**：

- 红线条款不接：付款节奏（不可绕过信用期）/ 知识产权归属 / 数据合规 / 管辖法院
- 可让步条款：可换条件（如金额换付款节奏 / SLA 换折扣）

---

## 步骤 5：签字盖章

**输入**：双方确认稿（v1.0 最终版）

**输出**：已签合同 + 审计日志（PDF + JSON）

**责任方**：

- **R**：双方代表 + 印章管理员
- **A**：销售（流程 owner）
- **C**：法务总监
- **I**：销售经理 SM

**动作清单**：

1. 选签约动作（电子签 / 纸质签 / 双轨 / 法定代表人 / 授权代表）—— 详见 `esign-vs-paper.md`
2. 准备签字角色清单（RACI）：销售 / 客户主联系人 / 客户法务 / 我方法务 / 财务 / 印章管理员 / 抄送
3. 签字顺序声明：Sequential（客户先签我方后签）/ Parallel（多部门同时）
4. 执行签字（电子签 / 纸质签）
5. 审计日志留档（PDF + JSON 双份）

**时间上限**：1 个工作日

**红线**：

- 法人主体 → 必须盖章 + 法定代表人签字（或授权代表 + 委托书）
- 电子签 → 选持牌平台（e-签宝 / 法大大 / 上上签 / Documenso 自建）
- 涉外 → 双轨（电子签中文 + 纸质英文）

---

## 步骤 6：归档入库

**输入**：已签合同 + 审计日志

**输出**：入档 + 关联 CRM + 双层归档

**责任方**：

- **R**：销售 + 印章管理员
- **A**：CSM
- **C**：法务（归档合规）
- **I**：销售经理 SM

**动作清单**：

1. 上传 PDF + DOCX（双份）到归档系统（paperless-ngx / 内部合同系统）
2. OCR 提取文字（中文 + 英文双语）
3. 自动打标签：客户名 / 合同号 / 金额 / 起止 / 风险评级 / 归档人
4. 关联 CRM 客户主记录（双向链接）
5. 权限分层：销售看自己合同 / 法务看全部 / CSM 看分配给自己
6. 30/60/90 天到期预警配置

**时间上限**：24 小时内（签完即归档）

**红线**：

- 入库必填字段：客户合同号 / 内部审批单号 / 签约日期 / 起止 / 风险评级 / 归档人
- 缺一项不入库

详见 `archive-and-tracking.md`。

---

## 步骤 7：交接交付（销售 → CSM / 交付）

**输入**：入档合同

**输出**：CSM 接收确认 + 启动交付

**责任方**：

- **R**：销售 → CSM
- **A**：销售经理 SM
- **C**：交付经理（如已分配）
- **I**：客户对接人

**动作清单**：

1. webhook 触发 / 邮件通知 CSM：合同已签，可启动交付
2. 销售填 10 项必传信息（详见 `contract-handoff-sop.md`）
3. CSM 接收确认（电子签 / 邮件）
4. 启动交付计划
5. 30/60/90 天到期预警提前 30 天推 CSM + 销售

**时间上限**：24 小时内

**红线**：

- 不可签完销售就不管——交接是合同闭环的一部分
- 不可让 CSM 自己找合同——必主动通知 + 推链接
- 不可错过到期预警——30/60/90 天提前推

详见 `contract-handoff-sop.md`。

---

## 时间节点总表

| 阶段 | 责任方 | 累计时间 |
|---|---|---|
| 步骤 1 起草 | 销售 + 法务助理 | T+0 ~ T+2 |
| 步骤 2 内审 | 三方过会 | T+2 ~ T+3 |
| 步骤 3 客户 review | 客户法务 | T+3 ~ T+8 |
| 步骤 4 修订迭代 | 销售 + 法务 | T+8 ~ T+13 |
| 步骤 5 签字盖章 | 双方代表 | T+13 ~ T+14 |
| 步骤 6 归档 | 销售 + 印章管理员 | T+14 ~ T+15 |
| 步骤 7 交接 | 销售 → CSM | T+15 ~ T+16 |

**总计**：标准合同从起草到签完约 **16 个工作日**（≈ 3 周）。**加速版**（金额 < 50 万 + 标准条款 + 电子签）：**5 个工作日**。

## RACI 总表

| 步骤 | R | A | C | I |
|---|---|---|---|---|
| 1. 起草 | 销售 + 法务助理 | 法务总监 | SM（≥100 万） | 财务 |
| 2. 内审 | 法务助理 + 销售 + 财务 | 法务总监 | SM（≥100 万） | CSM |
| 3. 客户 review | 客户法务 | 客户项目对接人 | 客户领导 | 我方销售 |
| 4. 修订迭代 | 销售 + 法务 | 法务总监 | SM（红线） | 客户 |
| 5. 签字盖章 | 双方代表 + 印章管理员 | 销售 | 法务总监 | SM |
| 6. 归档 | 销售 + 印章管理员 | CSM | 法务 | SM |
| 7. 交接 | 销售 → CSM | SM | 交付经理 | 客户 |
