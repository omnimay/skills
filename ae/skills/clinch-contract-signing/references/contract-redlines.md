# contract-redlines.md

> 修订迭代方法 + 红线保护清单

## 1. 修订迭代总流程

```
接收客户修订意见（DOCX 带修订痕迹）
    ↓
diff 对比（客户修订 vs 我方底线）
    ↓
分类标记（红线 / 可让步 / 可换条件）
    ↓
我方反馈（DOCX 带批注）
    ↓
2-5 轮迭代
    ↓
git 提交每轮版本
    ↓
双方确认稿（v1.0 最终版）
```

---

## 2. 差异对比方法

### 2.1 工具推荐

- **Word 内置"比较"功能**：审阅 → 比较 → 选择原文档 + 修订文档 → 标红显示差异
- **Git diff**：适合条款段落对比（按段落切分后存为 markdown / txt 进 git）
- **专业合同对比工具**：ContractWorks / Ironclad / 法律科技平台（如 Conga）

### 2.2 对比维度

| 维度 | 对比方法 | 输出 |
|---|---|---|
| **金额** | 数字逐位比对 | 客户修改前 vs 后 |
| **付款节奏** | 时间节点对比 | 30/60/90 vs 50/50 |
| **SLA** | 指标对比 | 99.9% vs 99.5% |
| **条款文字** | 段落 diff | 标红 + 加批注 |
| **条款逻辑** | 阅读理解 | 我方是否同意 |

## 3. 分类标记（红线 / 可让步 / 可换条件）

### 3.1 红线条款（不可让步）

| 类型 | 红线 | 让步后果 |
|---|---|---|
| **付款节奏** | 不可绕过信用期（如 30 天 NET） | 现金流风险 |
| **付款方式** | 仅银行转账对公账户 | 资金混同风险 |
| **知识产权** | 现有 IP 归各自 / 合作 IP 归贡献方 | IP 流失 |
| **数据合规** | PIPL / 数据出境安全评估 | 行政罚款 + 刑事责任 |
| **管辖法院 / 仲裁** | CIETAC 仲裁 / 我方所在地法院 | 诉讼成本 |
| **法律适用** | 中华人民共和国法律 | 适用外国法增加不可预见性 |
| **赔偿上限** | 不低于合同总额 50% | 履约风险 |
| **不可抗力** | 明确界定 + 通知期 + 证明 | 争议风险 |
| **争议解决条款** | 仲裁条款必须明确 | 无效风险 |
| **签字主体** | 法定代表人 / 授权代表 + 委托书 | 效力瑕疵 |

### 3.2 可让步条款（可换条件）

| 条款 | 让步空间 | 可换条件 |
|---|---|---|
| **金额折扣** | 5-15% | 换付款节奏（预付）/ 换合同期限（长期）/ 换增购条款 |
| **SLA 等级** | 99.95% → 99.9% | 换月度服务费折扣 10% |
| **响应时间** | P1 从 2 小时 → 4 小时 | 换服务费折扣 5% |
| **赔偿上限** | 100% → 80% | 换付款节奏（预付 50%） |
| **合同期限** | 1 年 → 3 年 | 换年度涨价锁定（不超 CPI） |
| **涨价机制** | 年度调价上限 5% → 8% | 换预付折扣 5% |
| **培训费** | 含 5 次 → 含 3 次 | 换尾款延后付款 |
| **实施费** | 含实施 → 不含实施 | 换实施费单独报价（客户自付） |

### 3.3 中性条款（可调整）

| 条款 | 调整范围 |
|---|---|
| **联系人信息** | 客户对接人变更 / 邮箱变更 |
| **通知方式** | 邮件 vs 短信 vs 系统通知 |
| **附件清单** | 增删技术规格 / 服务范围 |
| **签字栏格式** | 双栏 vs 单栏 / 骑缝章位置 |

## 4. 红线保护清单（谈判前预审）

### 4.1 销售谈判前的红线清单（10 项）

谈判前打印清单，每一项核对：

- [ ] 1. 付款节奏底线：______天 NET（默认 30，不可绕过 60）
- [ ] 2. SLA 等级底线：______%（默认 99.9%，不可低于 99.5%）
- [ ] 3. 数据存储底线：______（默认境内，不可跨境除非客户书面申请）
- [ ] 4. IP 归属底线：______（默认合作 IP 归贡献方）
- [ ] 5. 赔偿上限底线：______%（默认 80% 合同总额）
- [ ] 6. 争议解决底线：______（默认 CIETAC 仲裁）
- [ ] 7. 法律适用底线：______（默认中华人民共和国法律）
- [ ] 8. 签字主体底线：______（默认法定代表人 / 授权代表 + 委托书）
- [ ] 9. 涨价机制底线：______%（默认年度 5%）
- [ ] 10. 终止条款底线：______（默认提前 30 天书面通知 + 违约金 30%）

### 4.2 法务复审红线清单（10 项）

客户回传修改稿后，法务必查：

- [ ] 1. 任何条款被客户删改 → 是否触发红线？
- [ ] 2. 付款条款：是否绕过信用期？是否新增非银行转账方式？
- [ ] 3. SLA 条款：是否降低指标？是否扩大排除窗口？
- [ ] 4. 数据条款：是否删除 PIPL 引用？是否新增跨境？
- [ ] 5. IP 条款：是否扩大许可范围？是否改变归属？
- [ ] 6. 违约条款：是否删除赔偿上限？是否扩大我方责任？
- [ ] 7. 争议解决：是否改为客户所在地法院？是否删除仲裁条款？
- [ ] 8. 法律适用：是否改为外国法？
- [ ] 9. 签字主体：是否改为非法定代表人？是否删除委托书要求？
- [ ] 10. 终止条款：是否改为客户可随时终止？

任一项"是" → 拒绝让步 / 上报 SM / 重新谈判。

## 5. git 版本控制最佳实践

### 5.1 仓库结构

```
contract-{客户名}-{合同类型}/
├── v0.1/                   # 第一版（我方起草）
├── v0.2/                   # 第二版（内审后）
├── v0.3-customer/          # 客户修订
├── v0.4/                   # 我方反馈
├── v0.5-customer/          # 客户再修订
├── ...
├── v1.0-final/             # 最终版（双方确认）
├── audit-trail/            # 审计轨迹
│   ├── customer-revision-1.docx
│   ├── our-response-1.docx
│   └── meeting-minutes.md
└── signed/                 # 已签合同
    ├── contract-signed.pdf
    └── contract-signed.docx
```

### 5.2 commit 消息规范

```
[contract] 第N轮：{客户} {条款改动}

例：
[contract] 第2轮：ACME 删改 SLA 指标 - 已拒绝
[contract] 第3轮：ACME 接受我方底线 - 推进签字
```

### 5.3 分支管理

- **main**：最终版（v1.0）
- **draft**：每轮修订（v0.1 / v0.2 / ...）
- **customer**：客户修订版本（v0.3-customer / v0.5-customer）
- **signed**：已签归档

## 6. 修订迭代节奏

| 轮次 | 目标 | 时间上限 |
|---|---|---|
| 第 1 轮 | 接收客户修订 + 我方反馈 | 1 个工作日 |
| 第 2 轮 | 重点条款攻坚（红线 vs 红线） | 2 个工作日 |
| 第 3 轮 | 一般条款 + 细节 | 1 个工作日 |
| 第 4 轮 | 最终确认 + 排版 | 1 个工作日 |
| 第 5+ 轮 | 警惕"客户故意拖延" → 升级 SM | 立即 |

**超 5 轮未签字** → 风险信号：

- 客户内部审批流程长
- 客户内部有不同意见
- 客户在谈别的供应商做备胎
- 客户故意拖延（等预算 / 等价格让步）

**应对**：

- 销售主动问询"是否遇到审批问题？我方可配合加速"
- 销售经理 SM 出面升级
- 评估是否转死单挽回或跟进提醒

## 7. 红线保护案例

### 7.1 案例：客户坚持"删 PIPL 数据条款"

**场景**：某外资客户要求删除所有 PIPL 引用，理由是"我们不在中国收集数据"。

**我方回应**：

- **不能删**：服务过程中我方必然接触客户中国子公司员工数据（用户名 / 工号 / 部门），属于 PIPL 适用范围
- **可让步**：可将数据条款简化为"双方各自承担本国数据合规责任"，但**不可删除 PIPL 引用**

**结果**：客户接受简化版本，签约成功。

### 7.2 案例：客户坚持"提前终止无违约金"

**场景**：某客户要求"任意时间无理由提前终止，无违约金"。

**我方回应**：

- **不能完全让步**：服务成本无法回收
- **可让步方案**：
  - 客户承担"已交付服务费 + 30% 违约金"
  - 提前 90 天书面通知
  - 我方保留数据 30 天后删除

**结果**：客户接受 30% 违约金 + 90 天通知期，签约成功。

## 8. 反例与归因

| # | 反例 | 错因 | 正确做法 |
|---|---|---|---|
| 1 | 销售全盘接受客户修订 | 没有红线保护 | 谈判前必填红线清单 |
| 2 | 法务只看一遍就过 | 缺乏系统化复审 | 10 项红线清单必查 |
| 3 | 合同版本不进 git | 缺乏版本控制 | 每轮提交 + commit 消息规范 |
| 4 | 红线条款靠"经验"判断 | 没有标准化 | 用 10 项清单强制核对 |
| 5 | 客户拖延超 5 轮不升级 | 没有止损机制 | 超 5 轮升级 SM |
| 6 | 让步后没有"换条件" | 单方面让步 | 让步必换条件（折扣 / 期限 / 增购） |
