# 分级授权（advocacy-tier-and-authorization.md）

> 主线步骤 3「分级授权」的完整方法。本文件是中国合规红线最重的一段——**没走完授权流程的素材，一个字都不能对外**。

## 一、代言层级 L0-L4 与授权匹配

| 层级 | 可对外程度 | 授权要求 | 物料去向 |
|---|---|---|---|
| L0 内部参考 | 仅内部销售引用 | 无（标来源与日期） | 售前内部材料/话术 |
| L1 匿名证言 | 可对外引述，匿名 | 无（去标识化到不可反向识别：不露客户名/人名/地域/规模特征） | 官网模糊引语/白皮书/行业报告 |
| L2 署名证言 | 可署名短引语（客户名/人名+一句话） | 客户确认（微信/口头）→ 书面补录授权记录 | 官网证言墙/售前材料 |
| L3 案例出镜 | 完整案例（客户名+数据+场景） | 《客户案例发布授权书》盖章 + 多部门审核 + 发布前终审 | 案例中心/官网/发布会/白皮书/公众号 |
| L4 标杆站台 | 授牌/发布会演讲/战略合作挂牌/联合宣传 | 一把手/分管副总确认 + 法务 + 市场 | 发布会/授牌仪式/战略签约 |

**层级判定**：每份素材从「对外程度」倒推层级——只引用一句 → L1/L2；完整案例 → L3；要露脸/挂牌 → L4。不确定 → 就低不就高（先 L1/L2，客户点头再升）。

## 二、授权铁律（中国合规红线）

1. **口头认可不算已授权**：口头 → 可做 L1-L2 前置，升 L3+ 前必须书面补录《客户案例发布授权书》。
2. **书面授权书必备要素**：授权发布的信息范围（公司名/数据/场景是否可披露）→ 使用场景与渠道（官网/宣传册/发布会/行业报告）→ 有效期限与地域 → 授权撤回条件与通知方式 → 授权方与被授权方签字盖章（重大客户盖章确认）。
3. **多部门审核链**（发布前）：
   - 业务初核：项目交付验收真实、数据可追溯、识别保密义务内容。
   - 技术脱敏：技术方案描述是否涉商业秘密，涉核心技术脱敏。
   - 法务合规：保密协议/广告法（效果数据不夸大、不误导）/个保法（个人信息范围）。
   - 市场整合：综合意见定稿，编制脱敏版与完整版，备授权文件。
4. **客户审核确认**：拟发布文稿（含细节）提交客户指定对接人 → 告知渠道与受众 → 客户修改意见回业务会商 → 客户仅对确认版本承担授权责任。
5. **发布前终审**：授权文件签署归档 → 发布版本与客户确认版完全一致 → 无未确认内容 → 标注「经客户授权公开」→ 登记渠道/时间/授权状况。
6. **央企国企反腐红线**：价值交换以非货币为主（曝光/行业背书/联合宣传/授牌），礼品额度受限；激励政策先与客户采购/合规对齐。

## 三、匿名化兜底（无授权但案例典型）

- 用「某知名 XX 行业企业」「某世界 500 强企业」替代客户名。
- 行业背景概括化，不提供地域/规模等可反向识别信息。
- 去标识化达到一般公众无法合理推断客户身份的程度。
- 可标注「经客户同意，不公开客户名称」增可信度。

## 四、授权生命周期管理

- **过期授权清理**：定期审计案例库，发现内容在线但底层同意过期/客户关系变化 → 刷新或下架标记。
- **下线/更正协议**：客户要求修改/更新指标/移除内容 → 明确负责人 + 响应时限 + 记录决策。
- **归档**：授权书 + 审核记录 + 发布记录集中归档，作为合规凭证。

## 五、授权工作流清单（交付时用）

```
1. 判定层级（L0-L4，就低不就高）
2. 未授权 → 发起授权：发给客户《授权书》+ 拟发布文稿
3. 客户确认 → 书面补录 → 多部门审核 → 修订
4. 发布前终审：版本一致 + 授权归档 + 「经客户授权公开」标注
5. 无法授权 → 匿名化兜底（L1）
6. 登记授权状态（Documented/Verbal/Not documented + 文件编号 + 有效期）
```
