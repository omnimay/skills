# 拓展信号识别（expansion-signals）

> 7 类触发器全清单 + 中国信号源 + 无 telemetry 替代 + ladder 前置判定。
> 沿用 OneWave expansion-triggers（MIT），信号源中国化重写。

## 前置判定：账户能否 expand

增购前先定位账户在 land-adopt-expand ladder 的位置：
- **land 段**（签单+上线中）：不 expand，先交付。
- **adopt 段**（采用中、首价值未证）：不 expand，先做采用与首价值证明。
- **expand 段**（采用稳定、价值已证）：可 expand，进信号扫描。

同时查账户健康度：健康度差（NPS 低/工单激增/champion 流失/用量下滑）→ **不 expand，先修复**（衔接流失挽回/业务回顾）。

## 7 类触发器全清单

### 1. 用量到顶（Usage Ceiling）— 最高转化路径
- 坐席占用 >85%（临顶，需加坐席）
- API/存储/调用量临限（<20% 余量，需升 tier 或用量包）
- 功能撞 tier 限制（需升级解锁）
- 内部排队等坐席/waitlist（要 access 的人多）
- power user 把功能用到极限（champion 候选）
- 增购类型：升级套餐 / 加坐席 / tier 升级

### 2. 功能差距（Feature Gap）
- 请求更高 tier 才有的功能（自然升级路径）
- 用 workaround 绕限制（痛=机会）
- 用竞品做某功能而我方也有（替换机会）
- 用例映射到未购模块/插件
- ⚠️ 采用率 <50% 是 **activation 不是 upsell**（先做采用）
- 增购类型：加模块 / tier 升级

### 3. 新团队/部门（New Team/Department）
- 只一个部门用、多部门公司
- 新部门成立（招聘/组织调整信号）
- 非签约部门用户要试用/access
- 用例适用相邻团队（如营销工具销售也能用）
- 并购另一公司可标准化
- 增购类型：跨部门拓展 / 新 BU 单

### 4. 公司增长（Growth-Driven）
- 招聘 20%+（12 个月）
- 新办公地/地理扩张
- 融资（B 轮+尤其信号花钱扩张）
- 营收增长/业务扩张
- 招会用本产品的岗位
- 增购类型：按比例加坐席/用量

### 5. 战略举措（Strategic Initiative）
- 数字化转型/现代化
- 新品上市可用我方平台
- 合规/监管要求我方助满足
- 降本 initiative（我方替更贵方案）
- 出海/国际化我方支持
- 增购类型：新用例 / 平台拓展

### 6. 竞品替换（Competitive Displacement）
- 并行用竞品做我方也覆盖的功能
- 竞品续约临近（timing 窗口）
- 对竞品不满
- 我方补齐差距的新功能
- 整合比多供应商更划算
- 增购类型：竞品替换 / 整合

### 7. 服务支持（Services & Support）
- 复杂实施需求
- 工单量高（需专属/高级支持）
- 新用户需培训
- 定制集成/开发需求
- 要专属 CSM/TAM
- 增购类型：服务 / 支持升级

## 中国信号源

| 信号 | 中国来源 | 海外对应（替换） |
|---|---|---|
| 用量/telemetry | 后台 telemetry（有则用）；私有化无 telemetry→业务侧手动数据（工单数/报表人天/审批时长/坐席手动统计）+ 客户确认 | 后台 telemetry / product analytics |
| 组织增长 | 朋友圈（招聘/搬迁/新业务线动态）、招聘网站（岗位数）、工商信息（融资/股权）、新闻公告 | LinkedIn 岗位/融资新闻/Crunchbase |
| 客户原话 | 微信群/企微群聊截图、客户领导微信群认可、朋友圈互动 | email / NPS / G2 review |
| 竞品动态 | 客户群里提竞品、招标平台竞品中标、行业圈口碑 | competitive intel tools |
| 预算/采购 | 招标平台（中国政府采购网/地方公共资源交易中心）、预算申报期、财年节奏 | budget cycle 30-60 days before |

## 无 telemetry 替代证据法

私有化/国产化常见无后台 telemetry，用业务侧手动数据替代（沿用首价值证明场景做法）：
- 坐席占用：IT/管理员手动统计当前在用坐席数 vs 授权数
- feature 采用：业务部门负责人估算核心功能使用频次
- 业务结果：工单数/报表人天/审批时长/合规事件数（上线前后对比）
- **客户确认的手动数据比我方估算可信 10×**；标可信度 data-derived 或 customer-validated，不冒充 customer-confirmed。

## 机会存在判定（铁律）

trigger 触发 **AND** 有对应可卖产品/功能 **AND** 账户健康（含 ladder 到 expand 段）→ 三者同时成立才算机会。缺任一不算：无产品可卖=产品反馈非增购；不健康=先修复；未到 adopt=先做采用。
