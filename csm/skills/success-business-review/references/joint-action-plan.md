# Joint Action Plan（joint-action-plan）

> 配套 SKILL.md 主线第四步「设下期 joint plan」。采用 joint action plan + agreement state 四态 + ≤3 commitments w/ date+owner。

## 一、≤3 Commitments 铁律

- **至多 3 条**：超过 3 个 = 没抓重点，砍到 3 个以内。
- 每条带：date（截止日）+ 双方 owner（我方+客户方）+ agreement state。
- **单方 owner = 项目计划非合伙**：必须有客户方 owner，否则不是 joint plan 是我方 todo。

## 二、Agreement State 四态

| 状态 | 含义 | 何时用 |
|---|---|---|
| draft | 我方草案 | 会前/会中初拟 |
| proposed | 提给客户 | 会中提出 |
| agreed | 客户点头 | **有 confirmation evidence 才算 committed**（微信截图/邮件/会中纪要） |
| changed | 会中/会后调整 | 客户提出修改后 |

**铁律**：只有 agreed + confirmation evidence 才算 committed。proposed 不算承诺，draft 不算数。

## 三、Commitment 模板

```
[QBR {YYYY}-Q{N}] Commitment #{1-3}
- 描述：[具体动作+可度量结果，如「处室覆盖补到 5 个」]
- 我方 owner：[CSM 姓名]
- 客户方 owner：[客户方姓名+职务]
- 截止日：[YYYY-MM-DD]
- agreement state：[draft/proposed/agreed/changed]
- confirmation evidence：[微信截图链接/邮件日期/会中纪要]（agreed 必填）
- 依赖：[客户侧依赖项，如「客户信息中心排期」]
```

## 四、Confirmation Evidence 类型

- **customer-confirmed**（最高）：客户微信/企微明确确认截图。
- **customer-validated**：会中口头同意+会后续要书面确认。
- **meeting-minutes**：会中纪要双方签字/确认。

**估算/我方单方记录不算 confirmation evidence**。

## 五、下期 Joint Plan 与上轮闭环的关系

- 上轮承诺闭环（主线第二步）→ 认账兑现/未兑现。
- 下期 joint plan（主线第四步）≤3 新 commitments。
- **上轮未兑现的承诺不自动滚入下期**：先认账+补救计划，再决定是否纳入下期 commitments（避免「未兑现承诺自动延期」的信任侵蚀）。

## 六、反例（归因式）

| 念头/做法 | 后果 |
|---|---|
| 超过 3 条 commitments | 没抓重点，客户记不住，执行分散 |
| 单方 owner（只有我方） | 不是 joint plan 是 todo，客户不担责 |
| proposed 当 committed 报 | 客户没真正点头，下期兑现时扯皮 |
| 无 confirmation evidence | 口说无凭，续约时无法证明客户认可 |
| 上轮未兑现自动滚下期 | 信任侵蚀，客户觉得未兑现无成本 |
