# Downstream Hooks（downstream-hooks）

> 配套 SKILL.md 主线第五步「埋续约/增购/转介绍触发点」。采用 Two Asks 门槛（中国含蓄化改造）+ 沿用首价值证明的 renewal-hooks 交接法。本场景只埋触发点+交接指针，不替续约/增购/转介绍谈判（下游 skill 做）。

## 一、含蓄化原则（中国决策层文化）

**海外 Two Asks 在会上直 ask → 中国改造为「会上埋触发点，会后单独推进」**：
- 会上直 ask 续约/增购/转介绍 → 中国含蓄文化伤关系，ask 没挣来反显功利。
- 会上埋触发点（记录信号+预判条件）→ 会后由销售/CS 单独推进（饭局/微信/正式沟通）。
- 复盘会上只做价值证明+下期规划，ask 靠会后。

## 二、3 类触发点 + 门槛

### 1. 续约预演钩子

| 触发条件 | 动作 | 交接 |
|---|---|---|
| success plan 进度过半（≥50%）+ 续约前 60-90 天 | 会后启动续约对话预演，用 QBR 证据包做底稿 | `success-renewal-management` |
| 进度 <50% | 诚实标注缺口+补救计划+续约前核验承诺 | `success-renewal-management`（用缺口清单做风险预案） |

**预演输入包**：
- QBR 复盘文件（承诺兑现+success definition 状态+证据包）。
- success plan 进度表（baseline→target，已完成/进行中/未开始）。
- 客户原话集（决策层认可微信截图）。
- 续约前 60-90 天待核验动作清单。

### 2. 增购钩子

**门槛（不满足就跳过并记原因）**：
- **on_track 才埋**；at_risk 跳过（救计划优先），记 `expansion_ask: skipped, reason: at_risk`。
- 客户主动问新场景 / 使用量超预期 / 某部门未用但看到兄弟部门价值。

| 信号 | 动作 | 交接 |
|---|---|---|
| 客户主动问「能不能用在 [新场景]」 | 记录+评估可行+增购预案 | `success-expansion` |
| 使用量超预期（功能深度/频次） | 标记扩张机会+量化溢出价值 | `success-expansion` |
| 兄弟部门未用但看到价值 | 主动提议试点+价值外推测算 | `success-expansion` |

**增购触发测算模板**：
```
[新场景/新部门] 增购测算
- 当前覆盖：[已用部门/场景]
- 潜在覆盖：[新部门/场景，N 人/N 流程]
- 价值外推：按已用部门单 [人/流程] 节省 × 潜在覆盖 = [外推价值]
- 触发条件：[客户主动问 / 试点成功 / 预算窗口]
```

### 3. 转介绍钩子

**门槛（3 precondition 全满足才埋，否则跳过并记原因）**：
1. **客户关系温度计 = 热/铁**（见下节）。
2. **success definition = on_track**（at_risk 跳过，记原因）。
3. **同行业相似需求识别**（有具体目标行业/场景，非泛泛「知道谁需要」）。

| 信号 | 动作 | 交接 |
|---|---|---|
| 决策层微信/口头强认可 | 会后请求转介绍（同行业相似需求） | `success-referral-generation` |
| 客户愿做标杆案例 | 启动案例制作（客户授权） | `success-referral-generation`（案例材料交市场制作） |
| 行业会议公开提及产品 | 收集+扩大传播 | `success-referral-generation`（口碑传播段） |

**转介绍请求话术**（中国语境，不生硬，会后饭局/单独沟通）：
- 「张总，您这边用得不错，同行业 [X 类企业] 应该也有类似痛点，您方便的话能不能引荐一两位？我们帮他们也省点事。」
- 不在复盘会上硬要（关系没到或 at_risk 时），在客户主动认可后顺势提。
- 求 1 个引荐非名单；make it forwardable（2-3 句客户可直接转发的描述）。

## 三、客户关系温度计（替代海外 referenceable 字段）

| 温度 | 信号 | 转介绍可行性 |
|---|---|---|
| 冷 | 仅业务对接，无私下交流 | 不可 |
| 温 | 有私下交流，未主动认可 | 暂不 |
| 热 | 主动认可+引荐意愿（微信/口头表扬） | 可提（on_track 时） |
| 铁 | 愿做标杆案例+愿饭局引荐 | 优先提 |

**判定来源**：微信/企微互动频率+客户领导主动认可截图+饭局/线下互动+客户是否愿公开案例。

## 四、下游 Skill 交接说明

复盘收尾后，把以下产物交接下游：

| 产物 | 用途 | 接手 skill |
|---|---|---|
| QBR 复盘文件 | 续约对话底稿 / 下次 QBR 素材 | `success-renewal-management` / 下次本 skill |
| success plan 进度表 | 续约预演 / 目标续设 | `success-renewal-management` |
| 价值叙事 3 版 | 增购触发 / 案例素材 | `success-expansion` / `success-referral-generation` |
| 客户原话集（微信截图） | 标杆案例 / 口碑传播 | `success-referral-generation` |
| 触发点清单 | 续约/增购/转介绍追踪 | 下游全套 |
| 缺口清单+补救计划 | 续约前风险预案 | `success-renewal-management` / 流失挽回 |

**交接时机**：QBR close（会后 follow-up 发出+action tracker 建）后 7 天内，销售+CS 与下游 skill owner 做交接，移交产物+说明客户关系现状+触发点条件。

## 五、不替续约/增购/转介绍谈判（边界声明）

本 skill 只埋触发点+交接，**不做**：
- 续约价格/条款谈判（`success-renewal-management`）。
- 增购方案/报价（`success-expansion`）。
- 转介绍落地（`success-referral-generation`）；案例材料交市场制作。
- 流失挽回（`success-churn-recovery` 如有）。

## 六、反例（归因式）

| 念头/做法 | 后果 |
|---|---|
| 会上直 ask 续约/增购/转介绍 | 中国含蓄文化伤关系，ask 没挣来反显功利 |
| at_risk 还埋 expansion | 救计划没做先要钱，显功利伤关系 |
| 关系温度计=温就提 referral | 关系没到，客户尴尬，可恢复客户变流失 |
| 复盘完不埋钩子 | 续约时重新解释价值被动、增购/转介绍流失 |
| 埋了钩子不交接下游 | 触发点丢失，下游 skill 不知道接手 |
