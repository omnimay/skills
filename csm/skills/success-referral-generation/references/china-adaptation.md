# 中国适配（china-adaptation）

> 汇总海外 referral 方法论（OneWave、gtmify，均 MIT）到中国转介绍场景的改造，逐条给中国判断。
> 四条主线改造：渠道（微信/企微/拉群）、合规（个保法 + 商业贿赂）、关系文化（面子/人情）、对象（三层）。

## 一、渠道改造：email → 微信/企微/拉群

| 海外做法 | 中国替换 |
|---|---|
| 邮件引荐模板 | 微信/企微私聊转发包 + 拉群三方群 |
| LinkedIn 2nd degree 找连接人 | 微信朋友圈 / 行业微信群 / 供应链上下游 / 老同事圈 / 饭局 |
| NPS promoter 识别满意客户 | 微信/企微群原话截图 + 客户领导口头认可（来自 首价值证明 证据包） |
| referral program（产品内分享链接） | 不建程序化 loop；以「人拉人 + 拉群背书」为主，保留回报闭环思想 |

**拉群是中国特有的转介绍落地形式**：介绍人拉三人群 → 一句背书 → 双方直接对接 → 群内留下背书痕迹（= 中国式口碑，比邮件更有信用）。

## 二、合规红线（本 skill 最硬的两条）

**1. 个保法（PIPL）— 信息不得越权使用**
- 转介绍涉及被介绍人信息：必须先经介绍人同意 + 提醒介绍人先问被介绍人。
- 用介绍人名做外联、把线索录入系统，均须有「同意」来源；未经同意不用。
- 微信原话截图：仅内部判定/请求话术引用，不经客户同意不进对外材料。

**2. 商业贿赂 — 奖励给公司不给个人**
- 给客户员工个人现金返点 = 商业贿赂红线（政企尤其），客户经理会被查、关系破裂。
- 企业客户员工收礼有内部上限；政企更严。
- 合规回报排序：对等业务帮助 > 公开认可 > 客户公司级奖励（团队经费/团建）> 个人小额合规礼品（限额）；不做「介绍就给钱」。

详见 `references/tracking-and-reward.md` 合规回报表。

## 三、关系 / 面子文化

- **请求留面子**：话术带「不方便也正常 / 不勉强 / 你忙什么时候都行」——给拒绝留台阶。
- **拒绝留台阶**：婉拒 → 「完全理解，等有合适机会再说」，不追问，3 个月内不再提。
- **人情互惠先于索取**：先帮客户办事、先给转介绍，再开口；回报用对等帮助/公开认可优先于钱。
- **关系货币**：中国转介绍是信任背书，不是交易；把转介绍当买卖 = 烧关系。

## 四、三层请求对象（中国 B2B 特有）

| 层 | 角色 | 认可什么 | 切入 | 介绍谁 |
|---|---|---|---|---|
| 使用层 | 一线/技术负责人 | 好用省事 | 好用 | 同职能同行 |
| champion | 部门经理/牵头人 | 部门 KPI 兑现 | 项目数据 | 行业群/同级 |
| 决策层 | 一把手/分管副总 | 业务回报/政绩/对标 | 投入产出 | 高管圈/协会 |

中国政企常是「一把手拍板 + 分管副总执行 + 中层 champion 推动」——转介绍也要分头找认可：决策层认可业务回报（政绩/对标），champion 认可项目做成，使用层认可好用。三层请求切入不同，一套话术通吃必然冷场。

## 五、政企 / 国企特殊

- 政企客户个人对外转介绍可能涉及其内部纪律：请求要更轻、更正式，优先「客户公司级认可」而非个人背书。
- 政企场景的「回报」多为对等业务帮助 + 客户公司级感谢（表扬函/授牌），个人返点绝对不碰。
- 政企客户介绍渠道常在「行业交流会 / 协会 / 供应链」而非朋友圈。

## 六、与上下游的衔接

- 上游：success-business-review / 首价值证明的满意证据作为「满意表达」输入。
- 下游：线索交接 prospect- 桶（有效性验证 / 客户画像），来源与背书随线索带走。
- 并行：success-advocacy-management 管口碑证言/案例（声音资产），本 skill 管要新线索，不重复。
