# 转介绍获客（success-referral-generation）

## Overview

客户认可价值后，帮你有识别、有时机、有话术、有交接地把「转介绍」做成系统动作——主动要，且让客户好开口、好帮你。核心一句话：**转介绍的前提是客户先兑现价值；成败在「让介绍人省事 + 让被介绍人放心」**。

边界：不做证言/案例采集（success-advocacy-management）、线索分级（prospect- 桶）、续约/增购（success-renewal-management / success-expansion）。本 skill 只做「识别→要→对接→交接→回报」闭环。

## 主线：识别 → 判时机 → 设计请求 → 话术 → 对接 → 追踪回报

### 一、识别可转介绍客户 — 三组就绪信号 + 三层请求对象 + 阶段节奏

先判「谁值得问、问谁」。

**三组就绪信号**（缺组即降档）：

| 信号组 | 看什么 | 中国取证 |
|---|---|---|
| 价值兑现 | 首个可度量结果已出、达成里程碑 | 业务数据 + 客户确认（首价值证明 证据包） |
| 满意表达 | 主动说好话 / 要求加功能 / 验收续约爽快 | **微信/企微原话、客户领导口头认可** |
| 关系深度 | 多次正面互动、有 champion | 互动记录 + 对接层级 |

**三层请求对象**：

| 层 | 认可什么 | 请求切入点 | 适合介绍谁 |
|---|---|---|---|
| 使用层 | 好用、省事 | 「这工具用起来顺手吧」 | 同职能同行熟人 |
| champion | 部门 KPI 兑现 | 「你那边项目数据起来了」 | 行业群 / 同级圈子 |
| 决策层 | 业务回报 / 政绩 | 「投入产出比你心里有数」 | 高管圈 / 协会 / 供应链 |

**客户阶段节奏**：<3 月不问（先做成功）→ 3-6 月价值兑现则软提 → 6-12 月成功则直问 → 12+ 月季度固定问。刚上线 / 未解决工单 / 刚抱怨 / 拟流失 = 本季度不问。

详见 `references/referral-readiness.md`。

### 二、判请求时机 — 事件触发 + 三档判定

在正面事件**当口**问成功率最高；错过 = 热度降温后更难开口。

**事件触发**：① 里程碑兑现 → 当天；② 主动说好话 → 48h 内；③ 续约增购爽快 → 一周内；④ 提到同行/熟人 → 当场；⑤ 业务回顾会现场。

**三档判定**：

| 档 | 证据条件 | 动作 |
|---|---|---|
| ask_now | 三组信号齐 + 正值正面事件 | 直接问（按层切入） |
| soft_mention | 价值/满意未全、关系不错 | 埋种子 + 送转发素材 |
| wait | 负信号 / 太早 / 本季度问过 | 不开口，记入下季计划 |

**不可问**：刚抱怨、有未解决工单、使用量下滑、支付争议、考虑流失、上次婉拒后 3 个月内、每季度超 1 次。详见 `references/referral-readiness.md`。

### 三、设计请求 — 具体画像 + 降档选项 + 选渠道

**具体画像**（决定成败一半）：不给「谁有兴趣」的空问，要给**画像 + 挑战 + 我们帮客户解决过什么**。例：「你们同行业 200-500 人、销售团队也在手动建档案的公司，有认识的没？」

**降档选项**（让介绍人零负担，按顺序给）：① 我写转发文本你直接转（最省事）；② 你拉个群说一句背书，剩下我来；③ 授权我用你的名字联系你点名的名单；④ 你自己直接引荐。

**渠道选择**：微信/企微聊 → 私聊+拉群；回顾会现场 → 口头+会后微信回执；饭局/电话 → 口头轻提+事后补资料。形态表见 `references/ask-scripts.md`。

### 四、请求话术 — 三层对象分版 + 响应分支

**黄金结构**（任何版本通用）：**① 点价值（原话/数据）→ ② 给具体画像 → ③ 给降档选项 → ④ 留面子**。

- **使用层**：「你说过审批流程快多了」→「同行做审批的负责人有聊得来的吗？我把我们的做法整理成一段，你直接转就行」→「不方便也正常」。
- **champion**：点部门成果 →「行业圈里推数字化的人，我把效果数据发你，你看着转给合适的人」。
- **决策层**：点业务回报 →「项目成效行业内应该也想了解，我把一页纸发你，你在行业群里顺带提一句」。

**响应分支**：热情答应 → 立刻给转发包/约拉群，当口定下一步；犹豫 → 给转发素材 + 不追问；婉拒 → 接住不留负担（「等有合适机会再说」）；拒绝后 3 个月内不再提。全套话术见 `references/ask-scripts.md`。

### 五、介绍人对接 — 转发包 / 拉群 / 授权用名 + 24h 跟进

- **转发包**：介绍人 → 被介绍人的文本，**<80 字、第三人称、粘帖即用**，含 ① 谁介绍你 ② 你们解决过什么 ③ 一个轻 ask。**转发文本不好，就没有引荐。**
- **拉群脚本**：介绍人拉三人群 → 一句背书 → 销售补价值 + 约下一步 → 群资料跟进。
- **授权用名**：介绍人给名单 → 外联第一句「XX 公司的张总介绍我联系你」——**必须先经介绍人同意，且提醒介绍人先问对方**（个保法）。
- **24h 跟进**：24h 内首触 + 记入交接单；介绍人 5 天没回 → 一次 bump / 换介绍人 / 授权冷触。

模板见 `references/forwardable-and-group-chat.md`。

### 六、追踪与回报 — 反馈闭环 + 合规回报 + 线索交接

**反馈闭环**：首触后**回执介绍人**（「已联系上王总，进展 Y」）→ 结果出来再回执一次。不反馈 = 介绍人下次不帮。

**合规回报**：回报给公司/团队而非个人——对等业务帮助、公开认可、团队经费/团建奖励，个人礼品限额外。**给个人现金返点 = 商业贿赂红线**（政企尤其）；不做「介绍就给钱」的裸交易。

**线索交接单**（交接 prospect- 桶）：联系人 + 公司 + 职位 + 介绍人 + 背书原话 + 推荐时点 + 下一步首触 + 来源标签「转介绍」。交接 prospect- 桶下游做有效性验证与分级，本 skill 不做线索分级。模板见 `references/tracking-and-reward.md`。

## 判定标准（交什么）

一份可直接执行的转介绍动作包：

1. **可转介绍客户判定卡**：每客户一行——信号齐否 / 对象层 / 档位 + 理由。
2. **请求话术包**：三层×渠道分版 + 黄金结构 + 响应分支。
3. **转发包/拉群脚本**：<80 字转发文本 + 拉群开场 + 授权用名第一句。
4. **线索交接单**：带来源与背书背景，交接 prospect- 桶。
5. **追踪回报表**：24h 跟进状态 + 介绍人反馈回执 + 合规回报动作。

交付时给用户：判定卡 + 话术/转发包 + 交接单 + 待确认问题（最多 3 个）。

## 常见坑（归因式反例）

| 念头/做法 | 后果 |
|---|---|
| 客户刚上线就问转介绍 | 客户没体验到价值，答不上来也抹不开面子，关系变尬 |
| 空问「有认识的人需要吗」 | 客户大脑空白只能敷衍「想想」，没画像 = 零线索 |
| 只给高负担选项（自己写邮件联系） | 介绍人嫌麻烦口头答应不行动，转介绍流产 |
| 拿到线索不 24h 跟进 | 热度降温线索作废，介绍人觉得你不靠谱 |
| 不给介绍人反馈进展 | 介绍人觉得白搭人情，下次不帮，渠道枯竭 |
| 给客户个人返点/现金 | 员工违规、政企触碰贿赂红线，关系破裂 |
| 没经介绍人/被介绍人同意就用名字 | 隐私被冒犯（个保法），转介绍变投诉 |
| 要完不回报 | 只取不还烧掉关系网络，长期无人再帮 |
| 一套话术通吃三层对象 | 对决策层讲「好用」、对使用层讲「回报」，开口即冷 |
| 线索不标来源 | 回流后被当普通线索，无法回执、无法度量 |
