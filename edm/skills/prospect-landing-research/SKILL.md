# 客户切入调研

**一句话场景**：刚上手，不了解「购买产品这个决策」在客户内部怎么流转、该找谁、怎么切——本 skill 的活：**梳理客户结构 → 找到能用你产品的业务线/部门 → 挖清决策链和影响人 → 找到切入人和切入点**。

**路由红线（先自检再动手）**：本 skill 用于「**确认真需求的具体部门或业务线、从谁可以切**」；"值不值得切/该不该进"的名单评估不在此列；从零找名单 → icp-company-search。

## 怎么做（5 步方法论 + 每步标准）

> 每步 = 一个目标 + 产出的标准（做到这条才算过，别跳步）。

### 1 对象基本盘与业务线梳理
**目标**：先搞清这家公司是什么规模、什么结构，再决定"按部门梳理还是按业务线梳理"。
**做法**：
- 挖公司规模（营收/员工/上市与否）+ 业务（做什么、几条业务线/业务板块）
- 按规模和结构选梳理维度：大集团/多业务线 → 按业务线；单体公司/单一业务 → 按部门
- **列出全部业务线/业务板块**，标出「跟你要卖的产品相关」的（可能用到你产品的）
**产出标准**：一张「业务线清单」，每条标：业务线名 / 是什么 / 是否跟你产品相关（是=候选切入对象）。**至少标出 1 条相关业务线**才算过。

### 2 相关业务线与部门的决策链
**目标**：对**能用你产品**的业务线/部门，挖清决策链和影响人。
**做法**：
- 对第 1 步标出的每条相关业务线：它归哪个部门管？**有几个关联部门参与决策**（业务部门/采购/财务/IT 把关/分管副总）？
- **锚定"影响老板决策的核心主导/推进人物"**——不是把大老板当拍板人：老板会拍板"用不用"，但拍板前**业务侧/产品侧/技术侧/采购可能都向老板汇报各自看法**，其中一定有一个**核心主导/推进人物**（牵头立项、最了解这事、向老板做最终定论汇报、推动此事）——通常是相关业务线/部门负责人。**找这个主导人**：搞定他=打通整条汇报链。
- 在相关部门里套角色：EB 名义拍板人 / TB 把关人（技术/采购，卖软件必查） / UB 使用者 / Champion 推动者 / Gatekeeper（详见 references/decision-chain.md）
**产出标准**：每条相关业务线 → 归口部门 + 参与决策的部门清单 + **该事上影响老板决策的核心人物（具名或明确缺口）** + 决策链。**能说出"这事谁在牵头主导、谁向老板做最终定论汇报"**才算过。

### 3 挖掘切入人与触达
**目标**：把决策链关键人变成**能打出去的联系人**。
**做法**：从第 2 步挑**最接近关键决策核心人的人**（核心人本人 + 能联系到核心人的周边：经办/助理/同部门同事），挖联系方式 + 触达路径（总机/400、官网公开信息、转介绍；招聘/职场社交平台内的对接与核验由用户在其账号自行完成）。
**产出标准（两档）**：
- **最低**：至少 1 个**能打的真实电话**（总机/400，号码三态判定，见 references/data-sources.md）
- **期望**：最能接近和触达**关键决策核心人** + 能联系到这个人的人的**联系方式**（核心人直拨/转介绍/招聘对接人 IM）
**偷懒的后果**：只给公司总机不给到人，销售拨通总机却不知该转给谁——第一通电话产出目标 = 问出核心人名字。

### 4 切入思路
**目标**：给出销售"先做什么、怎么切"。
**做法（先挖动态、再定策略，有的放矢）**：
1. **先挖公司/相关业务线最近动态**（近 30-90 天）：融资、中标/新项目、招聘扩张、组织/高管变动、产品/系统上线、采购/招标、财报/战略动作——动态=切入时机和角度的依据（如在招同类岗→在扩→缺工具；新上任负责人→换供应商窗口；近期上线同类功能→自研/已有供应商）。
2. **可行性定性判断**（这单能不能打进去）：对方是否已自研/已有供应商（TB 前置）+ 动态佐证。
3. **策略四选一**（替换/嵌入/生态/放弃）+ 动态依据。
4. **先做哪一步**：Best Entry Point / Opening Hook / Discovery Questions（Hook 必须基于最近动态，不是泛化话术）。
**产出标准**：能说清"为什么现在切 + 依据什么动态 + 第一步做什么"。

### 5 交付报告
按交付契约输出（见下），证据 URL 可点，缺口已命名。

## 执行纪律（对模型做法的约束）

### 反浅搜（深挖到位 vs 浅搜放弃）
1. **先草稿后搜、缺口显式命名**：草稿标 `[NEEDS RESEARCH]` → 分解子问题 → 逐个搜 → 修订 → gap 分析。不搜一次就总结。
2. **"挖到位"停止判据**：高影响声明有源 / 关键源类已查或显式排除 / 反证已搜 / 剩余缺口逐条标注——才停。
3. **命中必追、引用必追**：硬信号追到可摘证据；来源引用的底层源追下去。
4. **读原文不引摘要**：WebFetch 读页面实际内容，不只看 snippet。
5. **缺口 = 清单 + 找法**：缺什么 / 为什么缺 / 下一步哪条路径。

### 数据纪律
1. **在职验证（强制）**：禁止用"没搜到近期活动"断言"在职存疑"——按"近 30 天履职行为"核验（新中标/新任命/新招聘/新合作新闻任一即"在职"，全无才"待核"）。
2. **来源替代**：主源不可达/不可核 → 多源对齐（百科+投资界+新闻+官网披露任二可点源）→ 二手源替代。
3. **号码三态**：✅原文核（open_page 原文出现）/ ⚠️多源对齐（≥2 独立源）/ ❌仅 snippet 或未核——逐条标注，不模糊。

**偷懒的后果**：浅搜只挖到网页 top（CEO/法人/公司简介），给不出业务线匹配和决策链——销售拿到报告仍不知先找谁、怎么切入，本 skill 最大失败模式。

## 交付契约（给用户的报告，只交有价值的信息）

```
# 客户切入调研 · [公司或项目名] · [你卖什么]
调研时点 / 调研人 / 版本

## Quick Take        # 2-3 句：谁、哪条业务线能用你产品、怎么切
## ① 对象基本盘      # 规模/业务/结构 + 梳理维度（按部门 or 业务线）
## ② 业务线清单      # 全部业务线，标出跟产品相关的 ★核心
## ③ 相关业务线的决策链 # 每条相关业务线：归口部门 + 参与决策部门 + 影响老板决策的核心人 ★核心
## ④ 切入人与触达    # 核心人 + 能联系到核心人的人 + 联系方式 + 触达路径
## ⑤ 切入思路        # 可行性定性 + 策略四选一 + 先做哪一步
## ⑥ Sources         # 只列有价值的（支撑核心结论的），可点链接
```

**Sources 筛选**：只列支撑「业务线匹配 / 决策链 / 核心人 / 切入」结论的关键来源，不堆砌无关链接。

## 执行自检（交付前 AI 自核，不呈现给用户）

- [ ] 挖出了业务线/部门内部成员（不只是顶层）
- [ ] 挖出了关键决策核心人及周边可触达联系人
- [ ] 每条相关业务线有归口部门 + 决策链
- [ ] 切入人至少 1 个能打的真实电话（或明确标❌+找法）
- [ ] ⑤切入思路含可行性定性 + 策略四选一 + 结合最近动态（依据什么动态切入）
- [ ] 缺口已命名 + 找法，号码三态明示
- [ ] 无反问/续工邀约收尾

## Common Mistakes

1. **不做业务线梳理直接挖决策人** → 挖出 CEO/法人却不知他管不管你这摊；先列业务线，才知道哪条能用你产品
2. **把大老板当拍板人就停** → 老板拍板"用不用"，但真正懂这事、向老板汇报定论的是业务负责人/部门负责人——找那个推动此事的人
3. **按部门硬套** → 先看规模结构决定按部门还是按业务线；大集团按业务线、单体按部门
4. **跳过"能不能打进去"的定性** → 对方已自研/已有供应商（TB 前置）就直接判断策略，别一头扎进卖成品
5. **号码凭记忆/仅 snippet** → 必须本轮可点 URL 核实或多源对齐
6. **编造人名/号码** → 推导标"推导"，缺口命名+找法，不编造
7. **结尾反问"需要我继续挖吗"** → 挖完再交
